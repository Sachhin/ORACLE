# Provenance-aware scientific knowledge graph

## Stable claims and revisions
Claims retain a stable ID while their wording changes. Every revision stores the prior wording, revision number, timestamp, and required change rationale. Evidence links continue to point to the stable claim identity; consumers should inspect the revision history before interpreting older links.

## Source provenance
A source record can store title, URL, publisher, type, publication/access dates, a provisional reliability score, and the rationale for that score. Evidence can point to a source and include a locator (page, table, DOI fragment, dataset accession), reliability, and a dependence group. Reliability is a transparent human/model assessment, not an objective truth score.

## Dependence-aware uncertainty
Evidence sharing a dependence_group is counted only once per stance, using the strongest weighted item in that group. This prevents obvious duplicate reports or multiple analyses of the same cohort from being treated as independent replications. It does not discover hidden dependence automatically. Uncertainty remains a reliability-weighted evidence-balance indicator, not a probability or calibrated confidence interval. A claim with no usable evidence has no estimate.

## Contradiction review
The system records contradiction candidates generated by explicit links or a narrow direct-negation heuristic. Candidates begin as pending_review and can be marked confirmed, rejected, or needs_context with a reviewer note. Nothing is silently resolved. Semantic contradiction detection is not implemented.

## Durable storage and event idempotency
Run snapshots remain the recovery source of truth. SQLite also mirrors sources, claims, revisions, evidence, links, and contradiction candidates into queryable tables in the same transaction as each snapshot. Event keys can be used to make replayed lifecycle events idempotent. Existing databases are upgraded in place.

## Recovery boundary
The orchestrator checkpoints only at completed cycle boundaries. If a process is killed mid-cycle, the last completed snapshot is restored and that cycle is retried. The event log may contain stage events from the abandoned attempt; callers should use stable event keys for replay-safe stage processing. A hard-kill integration test is still required before calling crash recovery production-hardened.

## Integrity limits
No external sources are fetched by the current offline agents. Source records and reliability scores must be supplied by a future retrieval/verification pipeline or a reviewer. The baseline remains deterministic scaffolding, not an autonomous scientist.
